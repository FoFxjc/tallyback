03 — The accountability loop

Five record boundaries. One durable Task underneath them.

The loop is not a state machine a Task marches through once — it is where each kind of record is allowed to attach. A Task can carry several Attempts; a Blocker or a Claim can arrive at any point.

04 — What a tallyback actually contains

Claim, Evidence, and Verdict are three different kinds of statement.

Conflating them is the failure mode Tallyback exists to prevent. Each record below is a distinct, separately attributed statement — not a synonym for the one above it.

SAYS

Claim — the executor's own statement about progress.

"Implemented and verified"
SUPPORTS

Evidence — a pointer to something checkable: a commit, a test run, an observation.

commit a3f9c1 · pytest: 23 passed
EVALUATES

Verdict — an independent, per-criterion judgment against the Declaration, with confidence and rationale.

supported · confidence: high
DECIDES

Settlement — the explicit, attributed, immutable decision: accept, retry, abandon, or land.

decision: land · by tool:pm

Trust ordering

  1. Repository / tests
  2. Git facts
  3. Tallyback records
  4. Model memory

A record in the ledger is a stored judgment, not proof. It only outranks model memory — repository and Git reality outrank it.

05 — Parallel work and Land

Two Attempts, two branches, one integration-readiness report.

tallyback land cross-checks the ledger's settled, land-authorized Tasks against live Git state — read-only, and it never performs the merge.

● target: main — Task A: git_ready — Task B: git_ready ┄ overlapping file flagged by Land

Both Attempts are individually git_ready. Because their ready branches touch the same file, Land reports them as a conflict group instead of silently ordering one ahead of the other.

git_ready

Branch exists, ahead of target, currently actionable.

git_behind

Actionable, but the target moved since — Git can't yet resolve it.

git_integrated

Git already proves the branch landed. Historical, not actionable.

git_unresolved

No branch ref to check — reported, never inferred.

If Task A merges first, its next report becomes git_integrated; Task B — unchanged, now behind a moved target — becomes git_behind until it's rebased or its own merge is checked again. Land observes and reports each state; it does not guarantee this exact sequence for every pair, and it never performs the merge itself.

06 — Boundaries, and trying it

What Tallyback deliberately leaves alone.

Every item below is a boundary the product is designed around, not a missing feature.

  • Run your agents, or choose them
  • Orchestrate or schedule execution
  • Merge, rebase, or push Git branches
  • Replace tests, CI, or code review
  • Turn a model's claim into a fact by recording it
  • Require a cloud account or database server
